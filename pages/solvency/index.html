Pearl Solvency

Proof-of-reserves desk for PRL — the audit room

The custodian

A proof of reserves is a signed statement: we control these addresses, and here is what we owe. Anyone can verify the signatures and re-add the on-chain balances. No account, no server — the statement is a tamper-evident bundle you can publish anywhere.

Honest limits — read before you trust any proof

  • Assets, not liabilities. This desk proves the custodian controls on-chain PRL. The liabilities figure is self-declared — understating it makes any custodian look solvent.
  • A snapshot, not an audit. Balances move. A proof is only true for the moment it was verified — check the challenge date.
  • Borrowed funds pass. Nothing here stops a custodian from borrowing PRL, proving reserves, and returning it.
  • Keypath P2TR only. Each address must be the BIP-86 keypath address of the entered key — script-path or multisig addresses cannot be proven this way.

The addresses

Paste every prl1p… address the custodian claims to control — one per line (up to 250). Each must be a v1 Taproot address on the selected network. Duplicates are merged silently; anything else is rejected loudly.

    The proof

    For each address, enter the private key that controls it — WIF, 64-hex, or a 12/24-word mnemonic (BIP-86 account 0). The page derives the keypath address and refuses any key that does not reproduce the listed address exactly, then signs the canonical challenge with the tweaked key. Keys are wiped from memory the moment signing finishes.

    Air-gap (sign on a cold device)

    Export the unsigned challenge bundle, sign each challenge offline (this same page works offline once loaded), then import the signatures below.

    The statement

    The tamper-evident proof bundle. The 64-bit fingerprint commits to the custodian name, liabilities, date, nonce, and every signature — editing any field breaks the fingerprint. Publish this JSON anywhere: a website, a tweet, an IPFS pin.

    The verdict

    Paste any pearl-solvency:v1 bundle — yours or someone else's. The page re-validates the fingerprint, checks every challenge signature, then reads each address's confirmed UTXOs from Blockbook (GET-only), byte-comparing every funding output script against the address. Foreign-script UTXOs are excluded, never trusted.
