Diagnose the stuck transaction

Paste a txid. The desk reads it with GET-only Blockbook calls and reports confirmations, fee paid, computed vBytes, effective feerate, and whether any input signals BIP-125 replaceability (any nSequence ≤ 0xfffffffd — the rule straight out of pearld's node/mempool/mempool.go, MaxRBFSequence). Nothing here moves coins.

Offline: paste a Blockbook /api/v2/tx JSON instead (air-gapped path)

Child-pays-for-parent

You received a low-fee payment and control one of its outputs. Spend that output in a child transaction paying a fat fee: miners are incentivized to confirm parent + child as a package. You pick the output, enter its key, set the target package feerate — the desk does the exact math, signs locally, re-verifies every signature, and asks twice before broadcasting.

Diagnose a transaction first (tab 1) — the CPFP planner needs its fee and size.

Replace-by-fee

The stuck transaction signaled BIP-125 (diagnosis says so) and you hold the keys to its inputs. Build a replacement spending the same inputs, keeping the same outputs, with the fee bumped by trimming one output you choose. pearld enforces three rules and the desk checks all three before signing: the new feerate must strictly beat the old one, the absolute fee must exceed old fee + min-relay fee, and no output may drop below dust.

Diagnose a transaction first (tab 1) — and it must signal RBF, or this tab refuses.

Track confirmation

Poll Blockbook for a txid's confirmation count. Loud when the backend is unreachable; stops itself at 1+ confirmations.

Package-feerate verifier

Standalone check: paste a parent txid (and optional child txid), state a claimed package feerate, and the desk recomputes (parentFee + childFee) / (parentVSize + childVSize) from Blockbook and rules PROVEN or NOT PROVEN — with the full derivation on screen so anyone can hand-check it.

Honest limits

  • No confirmation is guaranteed. Boosting only makes a transaction more attractive to miners; it cannot force inclusion.
  • RBF acceptance is node policy, not consensus. pearld implements BIP-125 (verified in node/mempool/mempool.go), but a node operator may set rejectreplacement, and the Blockbook relay you broadcast through may refuse replacements. A rejected broadcast is not a bug in your math.
  • CPFP needs package-aware miners. The child is worthless until the parent confirms; if a miner takes the child alone it can't — but most miners score by ancestor package. If the parent is double-spent, your child dies with it.
  • This page never sees the mempool directly — it sees Blockbook's view of it. Fees shown are what Blockbook reports.
  • Dust floor: 546 grains per P2TR output (upstream txrules). The desk refuses to create dust.
  • Keys: WIFs live in page memory only, are wiped by the Wipe button and automatically after broadcast. Never paste a key you can't afford to lose into any website — ideally use a dedicated boosting key.
  • Already confirmed? Both accelerator paths refuse loudly — a confirmed transaction cannot be boosted, only spent onward.
