Pearl Paywall

Put your content behind PRL — no accounts, no Stripe, no server. Seal a tamper-evident paywall descriptor, take the exact PRL price on-chain, and buyers mint a Schnorr-signed access token with the funding key. Verify payment + signature against public Blockbook data, or drop the dependency-free snippet on your own site. Five steps: Create → Pay → Token → Verify → Snippet.

Honest limits — always true:
  • The embed snippet is snippet-level protection (view-source can find the hidden markup) — strong for soft/manual delivery (email lists, download-link rotation, community access), not DRM.
  • Keep your snippet config as private as your use allows; Blockbook is a third-party read source.
  • Buyers must control the funding key: tokens only mint from a P2TR keypath key that funded the payment. A token is a backstage pass — it can be photocopied, so bind delivery to the buyer where it matters.
  • Descriptors are commitments, not signatures: they prove what the paywall promised, not who promised it. Publish them where your audience can check them.
  • The page never moves real PRL and never broadcasts anything; funding keys live in memory only and are wiped on demand.

Mint access token

        
The buyer signs locally with the key that funded the payment
          (WIF, 64-hex, or BIP-86 mnemonic — in-memory only, never stored). The page
          refuses loudly unless the key controls a P2TR input address
          of the paying txid: the token signature must verify against an input address
          of the payment.

Standalone verifier

      
Paste a descriptor, its canonical paywall JSON, and an access token.
        The verifier recomputes the descriptor, fetches the payment from Blockbook,
        confirms it paid ≥ price to the paywall address, confirms the token key is a
        paying input address, and re-verifies the BIP-340 signature — then answers
        PROVEN or a loud NOT PROVEN.
