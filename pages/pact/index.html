Honest limits — read before you pact

  • Trust the oracle, not the math, for the outcome: the oracle cannot steal (it holds no key that moves funds), but it alone picks the winner. Only pact with oracles whose attestations you would bet on.
  • Adaptor cryptography is real but newly composed here: Schnorr/BIP-340, Taproot and the 2-of-2 script come from audited lineage; the adaptor encrypt/verify/decrypt glue is new code in this page, pinned by tests. Review src/pact-core.js before mainnet money.
  • This page never broadcasts: every transaction leaves as hex for you to copy and broadcast yourself. The Blockbook broadcast buttons double-confirm first.
  • CETs are worthless until the funding output confirms: seal everything before funding, fund, wait for confirmation, then the winning CET becomes spendable after the oracle attests.
  • The refund is insurance, not a promise: it only becomes valid after its nLockTime. If the oracle attests first, the winner's CET beats any refund.
  • Keys live in this page's memory only. Anyone watching your screen or with access to this browser session sees them. Clear them when done.

Seal the CETs

For each outcome the desk builds the Contract Execution Transaction, then each party adaptor-encrypts their signature to that outcome's oracle announcement point. Every encrypted signature is verified on the spot. Do this before funding — once sealed, neither party can hold the other hostage.

Execute the winning outcome

The oracle attests: it reveals the outcome secret t and signs the attestation. The desk checks t·G against the committed announcement point, verifies the oracle's signature, decrypts both adaptor signatures, re-verifies them as plain BIP-340 signatures, and emits the final CET.

Refund — the insurance leg

If the oracle never attests, the timelocked refund returns each party's collateral. Both parties sign it now, while everyone is cooperative. It becomes valid only after nLockTime — before that, miners will reject it.
